# Asleep at the Keyboard? Assessing the Security of GitHub Copilot’s Code Contributions

> **Authors:** *Hammond Pearce, Baleegh Ahmad, Benjamin Tan, Brendan Dolan-Gavitt, and Ramesh Karri*

<br/>

The authors of this paper analyzed GitHub Copilot LLM. They evaluated the potential of security vulnerabilities in the code generated by Github Copilot. The study was conducted using three dimentional research areas:

**1. Diversity of weakness:** The authors built 89 different scenarios for Copilot to complete, producing 1,689 programs. The scenarios were constructed using the CWE "top 25" weaknesses as guideline.
Three different scenarios were created for each applicable "top 25" CWE vulnerability. The CodeQL software was used to scan the Copilot generated code along with manual inspection to determine if the generated code 
is vulnerable to the CWE selected. The authors' goal was to get a broad overview of the types of vulnerability Copilot is most likely to generate. 

**2. Diversity of prompt:** Using a particular scenario (SQL injection/CWE-89), the rsearchers analyzed the effect of different prompts when generating the code.

**3. Diversity of domain:** The authors studied the security of the code generated by Copilot when it is used for a domain (programming language) that was less frequent.
The researchers prompted Copilot to generate code for register-transfer level (RTL) code in the hardware description language Verilog. 

The study revealed that 40% of the Copilot programs were vulnerable. 

The authors recommended that the developers should remain vigilant when using Copilot code. 
Copilot should be paired with a security tool during both training and generation of code to minimize the security vulnerabilities.
