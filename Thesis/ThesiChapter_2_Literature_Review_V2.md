## 2.3 Empirical Security Profiling of Generative Software
To evaluate code safety before agent deployment, initial research utilized controlled experiments with isolated, standalone programming tasks. **Pearce et al.** analyzed GitHub Copilot across three research dimensions: weakness diversity (building 89 scenarios across the MITRE CWE Top 25, creating three scenarios per weakness, yielding 1,689 programs), prompt diversity (evaluating prompt variation using a CWE-89 SQL injection scenario), and domain diversity (prompting Verilog hardware design code generation). Automated CodeQL scans and manual audits revealed that 40% of Copilot's programs were vulnerable, prompting the authors to recommend pairing LLMs with security tools during training and generation. **Sabra, Schmitt, and Tyler** expanded this baseline by evaluating five models—Claude Sonnet 4, Claude 3.7 Sonnet, GPT-4o, Llama 3.2 90B, and OpenCoder 8B—generating Java code across 4,442 benchmark tasks from MultiPL-E and ComplexCodeEval. A 550-rule SonarQube static analysis across four severity tiers showed that while the models produced functional code, they repeatedly injected systemic flaws like path traversals and hardcoded passwords. Critically, the study proved an LLM's functional Pass@1 rate has no statistical correlation with its code security, rendering standard functional benchmarks poor indicators of overall software safety.

To analyze how these vulnerability patterns translate into real-world codebases, recent literature has shifted to mining live public repositories. **Fu et al.** evaluated Copilot-generated Python and JavaScript code within public GitHub repositories, scanning a dataset of 733 keyword-filtered snippets using CodeQL paired with Bandit and ESLint. Their analysis revealed that 30% of the snippets contained flaws distributed across 43 unique CWE classifications (including eight 2023 CWE Top 25 entries and six stubborn weaknesses), while further demonstrating that feeding raw SAST alert data directly into Copilot Chat produced drastically superior remediation patches. On a macro scale, **Schreiber and Tippe** mined over 1.2 million lines of AI-attributed code (7,696 files) across ChatGPT, GitHub Copilot, Tabnine, and Amazon CodeWhisperer using the GitHub REST API. Running the CodeQL security-and-quality suite paired with National Vulnerability Database API severity mapping, they found that 36.8% of findings were security-relevant errors, with Python files exhibiting consistently higher vulnerability rates (16.18%–18.50%) than JavaScript (8.66%–8.99%) and TypeScript (2.50%–7.14%). Their security density analysis revealed tool-specific strengths, with Copilot performing best for Python and TypeScript, while uncovering exceptionally high average CVSS Base Scores for severe flaws like SQL Injection (CWE-89), OS Command Injection (CWE-78), Code Injection (CWE-94), and hard-coded credentials (CWE-259/798).

However, when comparing these automated flaws directly against human engineering baselines, contemporary findings remain divided. **Asare, Nagappan, and Asokan** conducted a comparative security analysis by filtering the peer-reviewed Big-Vul dataset down to 153 C/C++ vulnerability scenarios historically introduced by software developers. Recreating these prompts for GitHub Copilot, graduate computer science students verified that Copilot generated identical vulnerable code in 33% of cases and matched the original repository fix 25% of the time, leading the authors to conclude that Copilot is less prone to introducing code flaws than human developers, though bug remediation remains risky. This conclusion stands in sharp contrast to recent live ecosystem findings from **Rabbi et al. (2026)** and **Siddiq et al. (2026)**, whose empirical data on autonomous agents operating in mature codebases show an elevated defect footprint and severe input processing failures compared to concurrent human contributions.
