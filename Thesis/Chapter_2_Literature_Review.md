# Chapter 2: Literature Review

## 2.1 The Architectural Transition from SE 2.0 to SE 3.0
The paradigm shift from developer-driven autocomplete tools to autonomous coding entities fundamentally reframes repository security. Under the Software Engineering 2.0 (SE 2.0) baseline, generative models operated as inline suggestion engines within cloud-hosted Integrated Development Environments (IDEs). Foundational user studies explicitly mapped this era; for instance, **Sandoval et al.** executed a controlled user study tracking 58 computer science students split into an AI-assisted group utilizing the OpenAI Codex LLM and a traditional control group coding entirely without AI access. Their team evaluated code security across 12 distinct C functions managing a shopping list application driven by a linked-list data structure, discovering that while Codex significantly boosted developer productivity metrics, the AI-assisted group generated up to a 10% spike in critical Common Weakness Enumeration (CWE) vulnerabilities. This behavioral risk layer was expanded by **Perry et al.**, who monitored 47 software developers and students completing five distinct security-critical programming tasks across Python, JavaScript, and C, similarly divided into an experimental track with an AI assistant and a control group without AI access. Their findings revealed that developers with access to an OpenAI Codex assistant consistently produced less secure code than the control group on four of the five tasks—specifically failing to handle edge cases, select secure cryptographic libraries, or sanitize raw user input—while paradoxically reporting inflated levels of trust in the unsafe AI output.

The maturation into the Software Engineering 3.0 (SE 3.0) era represents a structural transition from localized autocomplete assistance to agentic autonomy. As documented in the milestone repository study by **Li, Zhang, and Hassan (2026)**, the **AIDev dataset** serves as the definitive empirical research framework tracking real-world GitHub interactions across five core agent ecosystems: OpenAI Codex, Devin, GitHub Copilot, Cursor, and Claude Code. Aggregating **932,791 agent-authored pull requests (Agentic-PRs)** across **116,211 distinct GitHub repositories** and **72,189 human developers**, this taxonomy highlights that while agents multiply operational deployment velocity, passing an automated test suite does not guarantee high-quality code. 

This extreme operational autonomy completely eliminates the critical phase of live, line-by-line human developer filtering during initial code layout. **Ehsani et al. (2026)** monitored these independent agent loops, concluding that failed agentic PRs frequently suffer from severe logic truncation faults born from an agent’s failure to comprehend macro-level codebase architectures. This context mismatch is further compounded by downstream integration dependencies; **Ogenrwot and Businge (2026)** analyzed these pipelines and revealed that agentic code additions introduce an elevated frequency of multi-file merge conflicts due to the agent's inability to reconcile asynchronous, parallel human contributions targeting identical repository branches.

## 2.2 Macro-Level Repository Dynamics & Rejection Drivers
When analyzing the raw structural security defects of machine-generated code, current empirical literature uncovers a significant quality deficit when compared to human baselines. At an ecosystem level, **Ogenrwot and Businge (2026)** noted that 15.3% (142,652 PRs) of the total agentic contributions in the AIDev dataset were rejected, closed, or left perpetually stale. While the remaining 84.7% merge rate implies high acceptance, this figure is mathematically skewed by a massive volume of trivial, automated patches—such as minor documentation bumps or single-line dependency updates—accepted into smaller sandbox repositories. 

To control for this variance, **Li, Zhang, and Hassan (2026)** curated the **AIDev-pop subset**, extracting 33,596 agentic pull requests exclusively from repositories containing over 100 stars. Within this active cohort, the agentic merge rate drops sharply to 71.5%, with 21.6% (approximately 7,257 pull requests) explicitly closed via active maintainer rejections, and 6.9% (approximately 2,318 pull requests) abandoned as stale branches due to agent ghosting—where an agent fails to respond to multi-turn human critique. Evaluating the exact drivers behind these closures, **Peralta et al. (2026)** isolated three primary friction points: agentic structural failures (35.7%), workflow integration constraints (31.2%), and conversational ghosting (33.1%). 

This quality gap becomes even more pronounced when expanding the filter to highly mature repositories. In codebases containing over 500 stars, **Nakashima et al. (2026)** discovered a dramatic variance in review efficiency. Human developers achieve a **merge-to-rejection ratio of 5.45:1**, meaning nearly 5.5 human pull requests are successfully integrated into the codebase for every single rejection. Conversely, the autonomous AI agent ratio drops sharply to **1.92:1**, proving that maintainers are forced to reject an agentic patch for nearly every two successful integrations, dramatically inflating review overhead.

## 2.3 Empirical Security Profiling of Generative Software
When evaluating the security footprint of AI code additions, early literature heavily focused on synthetic, static code snippets. **Pearce et al.** established an initial diagnostic framework by passing 89 distinct security scenarios across the MITRE CWE Top 25 taxonomy through GitHub Copilot, generating 1,689 distinct programs. Using CodeQL scans paired with manual inspections, they uncovered that **40% of the Copilot-generated programs contained active security vulnerabilities**. This quality deficit was further exposed at scale by **Sabra, Schmitt, and Tyler**, who performed a cross-model static analysis using 550 SonarQube rules across 4,442 Java benchmark tasks curated from MultiPL-E and ComplexCodeEval. Evaluating elite models including Claude 3.7 Sonnet, GPT-4o, and Llama 3.2 90B, their findings proved that an LLM's functional execution success rate (Pass@1) has **no statistical correlation** with its underlying security posture, regularly generating functional code that harbored severe blocker-tier vulnerabilities such as path traversals and hardcoded credentials.

To move past isolated synthetic snippets, recent literature has shifted to mining live public repositories. **Fu et al.** assembled an empirical dataset of 733 live Python and JavaScript code snippets mined from public GitHub repositories, scanning them via CodeQL paired with language-specific SAST tools (Bandit and ESLint). Their analysis proved that **30% of the active snippets contained structural flaws scattered across 43 unique CWEs**, heavily fluctuating based on language and application domain. Similarly, **Schreiber and Tippe** extracted over 1.2 million lines of AI-attributed code (7,696 files) across ChatGPT, GitHub Copilot, Tabnine, and Amazon CodeWhisperer. Utilizing the CodeQL security-and-quality suite, they uncovered that 36.8% of active findings constituted security-relevant errors or warnings, with Python consistently exhibiting higher vulnerability rates (16.18%–18.50%) than TypeScript (2.50%–7.14%).

However, when comparing these AI flaws to traditional engineering baselines, the findings remain highly contested. **Asare, Nagappan, and Asokan** leveraged the peer-reviewed Big-Vul dataset to recreate 153 historic human vulnerability scenarios for GitHub Copilot. Their study indicated that Copilot successfully avoided replicating the human flaw in two-thirds of the trials, generating identical vulnerable code in 33% of cases and matching the original repository fix 25% of the time, leading them to argue that Copilot was less prone to re-introducing baseline vulnerabilities than human developers. This directly conflicts with the recent ecosystem findings of **Rabbi et al. (2026)** and **Siddiq et al. (2026)**, whose large-scale empirical scans of agentic PRs on GitHub exposed an elevated defect footprint within fully automated patches, particularly regarding input injection vulnerabilities and edge-case boundary failures.

## 2.4 Structural Divergences and Taxonomic Commonalities
A critical dimension of contemporary software security research involves mapping whether AI agents fail in the same manner as human engineers. The literature indicates a dual reality defined by taxonomic crossover alongside localized structural divergence. **Felix and Brian (2025)** evaluated human versus automated security patching behaviors within the AIDev dataset, noting a shared taxonomic core: both cohorts frequently struggle with standard, classic validation errors. This convergence is explicitly detailed by **Almukhtar, Ghammam, and Ming (2026)**, who noted that both tracks suffer from a high baseline frequency of input validation omissions (CWE-20) and resource misallocations (CWE-770) during refactoring procedures.

However, the underlying code architecture and localized spatial distribution of these vulnerabilities diverge significantly. While human developers disperse errors broadly across application logic due to multi-tasking state confusion, agentic code errors exhibit extreme spatial clustering. This spatial clustering is driven by what **Singla et al. (2026)** define as automated dependency and truncation constraints. Because LLMs optimize choices tokens at a time based on narrow context windows, their security flaws group densely within a single modified function or block, heavily concentrating around algorithmic boundaries and regular expression design limitations. Human developers, by contrast, are primarily associated with systemic architectural vulnerabilities, such as complex authentication flaws (CWE-306) and multi-file race conditions.

## 2.5 Maintainer Psychology and the Agent "Confidence Trap"
The downstream endpoint of any pull request is the human maintainer gate, where reviewer psychology heavily dictates final lifecycle resolutions. **Ahmed, Waheed, and Souati (2025)** tracked code evaluation dynamics at the University of Waterloo, demonstrating that the massive throughput of incoming, bot-submitted code quickly triggers severe maintainer cognitive overload and alert fatigue. To process this unmanageable volume of diffs, maintainers adapt by shifting their screening behaviors. **Haider and Zimmermann (2026)** applied thematic analysis to review comments, revealing that security concerns represent **5.59% of all feedback comments in rejected agent PRs**, nearly doubling the 3.05% frequency observed in accepted agent submissions. Furthermore, **Singla et al. (2026)** proved that while agents submit fewer security-focused PRs overall, they introduce known-vulnerable dependency versions 50% more frequently than humans (2.46% vs. 1.64%), leading to a net increase of 98 vulnerabilities across the ecosystem, compared to a net reduction of 1,316 fixes driven by human interventions.

This imbalance culminates in a dangerous behavioral anomaly characterized by **Almukhtar, Ghammam, and Ming (2026)** as the **Agent "Confidence Trap"**. Human engineering rejections typically stem from complex, unrefined, or messy implementation profiles. Conversely, autonomous agents generate code that is cosmetically clean, adheres to localized styling rules, and passes local repository testing pipelines with high model confidence. Because the code appears pristine, maintainers suffer from review fatigue and rely on social trust heuristics. This triggers the **Risk Acceptance Paradox**, where reviewers apply strict machine penalties and intense skepticism to openly labeled agentic PRs, yet fail to spot underlying risks in clean refactoring patches. Empirical static analysis using the Bandit security scanner revealed that **4.7% of the modified files within merged agent PRs silently introduced new security vulnerabilities** that human reviewers missed entirely. To exploit this trust shortcut, **Nachuma and Zibran (2026)** and **Hasan, Rabbi, and Zibran (2026)** documented an increasing volume of "silent pull requests"—unlabeled agentic additions that intentionally strip out automated bot tags to mimic human commits and bypass the heightened skepticism of maintainers.

## 2.6 Methodological Gaps in Extant Research
Despite the breadth of these recent studies, a major methodological deficit persists. Standard static application security testing (SAST) tools like CodeQL or SonarQube parse code at a file or project-wide scope. When evaluating incoming pull requests within existing codebases, these tools inevitably flag legacy technical debt—security vulnerabilities that existed in the repository long before the current pull request diff patch was generated. 

**Abujadallah, Arabat, and Sayagh (2026)** explicitly identified this limitation while analyzing rejected fixes in the AIDev dataset, noting that researchers regularly misattribute legacy codebase vulnerabilities to the incoming agentic patch. Current software engineering literature lacks a standardized, open-source architecture designed to parse raw SAST alert logs and programmatically filter them using exact line-by-line git diff coordinates. This thesis directly fills this methodological gap by engineering a custom patch-coordinate filtering layer within a GitHub Actions infrastructure, ensuring that discovered vulnerabilities are attributed strictly to the author of the new patch diff.
